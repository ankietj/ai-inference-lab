# Phase 2: Google Colab vLLM Hardware Validation Guide

This guide explains how to take the falsifiable hypotheses generated by our Phase 1 V2 analytical simulator and test them against physical hardware on Google Colab using [vLLM](https://github.com/vllm-project/vllm).

---

## 1. Experimental Setup & Exact Execution Steps

1. Open a new notebook at [Google Colab](https://colab.research.google.com).
2. Attach a GPU accelerator: **Runtime -> Change runtime type -> Hardware accelerator: T4 GPU** (free tier) or **L4 / A100** (Colab Pro).
3. In Cell 1, install vLLM:
   ```bash
   !pip install --quiet vllm
   ```
4. In Cell 2, upload or paste `colab/vllm_validation.py` and run:
   ```bash
   !python colab/vllm_validation.py --trials 3 --output colab_vllm_measured_results.json
   ```
   *(Optional)*: Specify a custom model:
   ```bash
   !python colab/vllm_validation.py --model meta-llama/Llama-3.2-1B-Instruct --trials 3
   ```

## 2. Model Selection by GPU VRAM Capacity

The script auto-detects GPU VRAM and chooses an open model:

| GPU Hardware | VRAM | Architecture | Default Model | Quantization | Rationale |
| :--- | :---: | :---: | :--- | :---: | :--- |
| **NVIDIA T4** (Free Colab) | ~15-16 GiB | Turing | `Qwen/Qwen2.5-1.5B-Instruct` | Native FP16 | Weights occupy ~3.0 GiB, leaving ~12 GiB free for KV-cache blocks. Safely supports concurrency sweeps up to 32 streams without OOM. |
| **NVIDIA L4** (Colab Pro) | ~22-24 GiB | Ada Lovelace | `meta-llama/Meta-Llama-3-8B-Instruct` | Native FP16 | Direct architectural match to our Phase 1 LLaMA-3-8B analytical model. |
| **NVIDIA A100** (Colab Pro) | 40/80 GiB | Ampere | `meta-llama/Meta-Llama-3-8B-Instruct` | Native FP16 | Direct match to our Phase 1 NVIDIA A100-SXM4 roofline profile. |

## 3. Measurement Boundaries & Metric Definitions

To ensure scientific integrity and avoid confusing offline batch metrics with online streaming server metrics:

| Metric | Measured In Script? | Timing Boundary & Definition |
| :--- | :---: | :--- |
| **Aggregate Batch Throughput** | **YES** | $\text{Total Output Tokens} / \text{Batch Duration (s)}$. Evaluated with CUDA synchronization before and after `llm.generate()`. |
| **Batch Duration** | **YES** | End-to-end wall-clock time for the GPU to process $C$ concurrent requests of 512 prompt tokens and 128 output tokens. |
| **Prefill + 1-Token Latency** | **YES** | Time to prefill an exact token sequence and emit the first token ($S_{\text{gen}}=1$). **Excludes CPU text tokenization** (prompts are pre-tokenized on CPU before timing). |
| **Per-Token ITL / TPOT** | **N/A** | Offline `LLM.generate()` returns only when the full batch is complete. Per-token inter-token latency requires streaming tokens over an HTTP/gRPC server (`vllm serve`). Marked as `N/A`. |
| **Admission Queue Wait** | **N/A** | All $C$ requests in a batch are submitted simultaneously to the offline engine; queue delay is marked as `N/A`. |
